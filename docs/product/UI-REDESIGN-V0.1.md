# SRS Manager 界面与体验整改基线 v0.1

> 状态：P1 实施基线  
> 定位：从“功能型 CRUD 管理后台”升级为“直播运维控制台（Streaming Operations Console）”。

## 1. 本轮目标

第一轮整改不重写核心直播业务逻辑，优先解决用户进入系统后的第一层体验问题：

- 一级导航平铺过多，找功能依赖记忆；
- Dashboard 以统计卡片为中心，不能快速回答“现在发生了什么”；
- 页面视觉层级弱，像通用后台模板，缺少专业播控台的运行感；
- 主工作区宽度和信息密度不适合桌面运维场景；
- 表格、按钮、弹窗、表单虽然已经组件化，但设计语言仍偏基础；
- 正常、在线、告警、危险等状态语义需要进一步统一。

P1 原则：**先重构 Shell、信息架构、设计 Token 和运营中心，再逐步重构 Stream Workspace 与工作流。**

## 2. 产品视觉方向

采用“专业播控台”而不是“炫技大屏”风格：

1. 深色中性背景，降低长时间值守视觉疲劳；
2. 正常状态保持安静，异常状态具有高识别度；
3. 大面积纯色和强渐变只用于品牌和关键动作，不用于普通信息装饰；
4. 减少满屏硬边框，依靠 Surface 层级、间距、阴影和局部描边组织信息；
5. 数字使用等宽/表格数字特性，便于值守人员快速扫描；
6. 页面优先适配 1440P / 4K 桌面工作站，同时保持移动端基本可用。

## 3. 新信息架构

一级导航从 11 个平铺入口改成 4 个工作域：

### 运营

- 运营中心（Dashboard）
- 实时监看（Monitor）

### 直播

- 直播流（Streams）
- 转发路由（Forwarding）

### 资源

- CDN 分发（CDN Channels）
- 域名与 DNS（DNS Records）
- 转码模板（Transcode Templates）

### 系统

- 访问凭证（Auth Keys）
- 网宿集成（Wangsu Auth）
- 阿里云 DNS（Aliyun DNS Auth）
- 系统设置（Settings）

注意：这是 P1 的导航收敛，不代表最终领域模型。后续 Stream Workspace 建立后，部分资源入口还会进一步降级为对象上下文操作。

## 4. 界面框架设计

### 侧边导航

- 约 260px 宽；
- 品牌区明确标识 `SRS Manager / Operations Console`；
- 一级导航按工作域分组；
- 当前页面采用柔和高亮 + 左侧/局部状态强调，不再使用整块强色背景；
- 高频工作域在上，基础设施配置在下。

### 顶部栏

Header 不再只是页面标题，应承担运行上下文：

- 当前页面名称；
- 当前 SRS 节点 / API 目标；
- 服务连接状态语义；
- 语言与用户操作。

后续可扩展全局搜索、Command Palette、告警中心，但 P1 不放置无功能的占位入口。

### 主工作区

- 最大内容宽度从通用 `max-w-7xl` 放宽到约 1600px；
- 列表页保留可扫描密度；
- 运营中心采用卡片与运行态区域组合；
- 高分辨率显示器优先利用横向空间。

## 5. 设计变量

在现有 Tailwind CSS v4 + CSS Variables 上继续演进，不引入第二套 UI 框架。

核心 Surface：

- `background`：应用画布；
- `sidebar`：侧边导航层；
- `card`：普通内容层；
- `panel`：关键工作面板；
- `elevated`：弹窗、下拉等悬浮层；
- `surface-hover`：可交互悬停层。

核心语义：

- `primary`：主要操作；
- `success`：正常 / 在线 / 成功；
- `warning`：需要注意但仍可运行；
- `destructive`：中断 / 删除 / 故障；
- `info`：中性运行信息。

原则：颜色必须优先表达状态和动作语义，而不是装饰。

## 6. 运营中心 v0.1

P1 Dashboard 从“六张 KPI 统计卡”重构为运营中心：

1. 顶部运行摘要：SRS 数据可达状态、当前在线流、总观众、总码率；
2. 分发摘要：CDN 活跃数、分发申请、转发任务；
3. 正在直播：按观众数排序，突出在线状态、观众、码率；
4. 最近事件：Publish / Unpublish / Play / Stop 时间线；
5. 离线流不再与在线流混在同一视觉权重中，仅作为辅助信息。

P1 不把“离线”直接定义为“告警”，因为永久配置但当前未开播的流可能是正常状态。告警模型在后续 Desired/Observed State 与 Event Policy 建立后再实现。

## 7. 通用组件整改

第一轮同步升级：

- `PageHeader`：更明确的标题层级和动作区；
- `TableShell`：更成熟的 Panel 外观；
- `styles.js`：按钮、输入框、表头密度、圆角、Focus Ring；
- `Modal`：提高层级感和可读性；
- `SearchInput`：保持紧凑但提高输入态识别；
- Skeleton / Error / Empty State 后续继续统一。

## 8. P1 之后

P1 完成后按以下顺序继续：

1. **P2 单流工作台**：一条流的输入、输出、分发、转发、转码、监看、权限、事件放到一个工作区；
2. **P3 流向图**：IN-PUSH / IN-PULL / OUT-PUSH / OUT-PULL 图模型与联动操作；
3. **P4 Live Event / Template / Preflight**：将重复配置转换为模板化直播任务；
4. **P5 操作状态机 / 期望状态 / 状态协调器 / 告警**：从按钮式 CRUD 升级为可恢复运维机制；
5. **P6 Batch / Runbook / Automation**：减少值班人员重复劳动。

## 9. P1 验收

- 一级导航不再平铺 11 个同级入口；
- 1440P 及以上屏幕工作区不再被 1280px 左右宽度过度限制；
- Dashboard 首屏可以直接识别当前运行状态和在线流；
- 正常、在线、警告、危险视觉语义一致；
- 原有路由与核心 CRUD 功能不因 Shell 整改失效；
- 中英文 key 保持一致，`npm run build` 的 i18n 检查应继续通过。
